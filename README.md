# cscI41-venue-management

Database implementation for our CSCI 41 Information Management project.

The project uses Django with SQLite and follows our finalized normalized database design.

## Technologies

- Python
- Django
- SQLite
- python-dotenv

## Database Structure

The database consists of nine tables:

1. BUILDING
2. AGENT
3. VENUE
4. VENUE_ASSIGNMENT
5. RENOVATION
6. AMENITY_TYPE
7. VENUE_AMENITY
8. CUSTOMER
9. RESERVATION

## Local Setup

**1. Clone the repository**

```powershell
git clone https://github.com/JaviHorse/cscI41-venue-management.git
cd cscI41-venue-management
```

**2. Create and activate the virtual environment**

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
```

**3. Install dependencies**

```powershell
python -m pip install -r requirements.txt
```

**4. Configure environment variables**

Create a `.env` file in the project root, where `manage.py` is located.

```dotenv
SECRET_KEY=your_generated_django_secret_key
DEBUG=True
```

To generate a secret key:

```powershell
python -c "from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())"
```

**5. Initialize the SQLite database**

```powershell
python manage.py migrate
```

This creates the database tables using Django migrations.

**6. Populate sample data**

```powershell
python manage.py seed_data
```

The script inserts five sample records into each of the nine project tables.

Running the script again will not create duplicate records with the same seed IDs.

**7. Run the development server**

```powershell
python manage.py runserver
```

Open http://127.0.0.1:8000/ in your browser.

## Database Files

| File | Description |
|---|---|
| `core/models.py` | Django models representing the nine normalized tables |
| `core/migrations/0001_initial.py` | Initial migration creating the tables and constraints |
| `core/management/commands/seed_data.py` | Command for populating sample records |
| `database/schema.sql` | Exported final SQLite CREATE TABLE definitions |
| `database/verification.sql` | SQL queries for verifying table structures, record counts, and foreign keys |

## Integrity Constraints

The implemented database contains:

- Nine primary keys
- Nine foreign-key relationships
- Seven explicitly defined CHECK constraints
- Three additional nonnegative-value CHECK constraints generated by Django

The CHECK constraints enforce positive numeric values and valid date ranges.

## Notes

- `db.sqlite3` is excluded from GitHub because each developer maintains their own local database.
- `.env` is excluded because it contains environment-specific configuration.
- Django migrations are the primary method for creating the project database.
- `database/schema.sql` is provided for SQL documentation and inspection.
- The seed script contains sample data intended for development and demonstration.

## Database Verification

After running migrations and seeding, verify the Django configuration:

```powershell
python manage.py check
python manage.py showmigrations core
```

You can inspect the database using the SQL statements in `database/verification.sql`.
